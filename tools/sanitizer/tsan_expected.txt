# tools/sanitizer/tsan_expected.txt — THE VERDICT FUNCTION of the
# ThreadSanitizer lane (task 1411). `lane.d tsan-verdict` is the only thing
# that decides whether a night is green, and this file is what it decides
# against.
#
# WHY THE PRESENCE OF A REPORT CANNOT BE THE VERDICT
# --------------------------------------------------
# This lane is NOISY BY CONSTRUCTION on a healthy night. Five routes carry
# races the source itself records as real and deliberately deferred to task
# 0950 (/api/selection, /api/undo/status, /api/history, /api/play-events,
# /api/play-events/status), and the lane's own live shutdown control REQUIRES
# one more to appear. On top of that TSan exits 66 whenever it has reported
# anything at all, so the exit code says "something was reported", never
# "something is wrong". A lane whose success and failure produce the same exit
# code is not a lane; and a lane that reddens on its first unfamiliar finding
# gets switched off rather than read — the neighbouring sanitizer workflow's
# Gate step says exactly that, in as many words.
#
# So the verdict is a DIVERGENCE FROM THIS FILE, and it runs in BOTH
# directions:
#
#   * a signature in the report that is NOT declared here      -> RED (new race)
#   * a `required` signature declared here that did NOT fire   -> RED (either
#     it was fixed — delete the line — or the instrument went blind)
#   * a `tolerated` signature that did not fire                -> recorded only
#   * the sweep sentinel missing                               -> RED (the
#     sweep died partway; without this, a process killed at route 3 of 57 is
#     indistinguishable from a clean run)
#   * no report file at all while a scenario carrying a `required` signature
#     ran                                                      -> RED
#
# WHAT IS DELIBERATELY NOT WITNESSED, stated here rather than implied
# -------------------------------------------------------------------
# The `tolerated` class cannot redden by absence. That is the price of the
# facts that the live shutdown control and several sweep races depend on the
# scheduler and on TSan's io_sync=1 edge, and a gate on a flapping signal is a
# lane that gets disabled. What witnesses the mechanism is the `required`
# class, and at least one `required` line (the synthetic control) is
# deterministic by construction. If every `required` line ever becomes
# scheduler-dependent, this lane has stopped proving anything.
#
# SIGNATURE FORMAT — a pair of SYMBOLS, never line numbers
# --------------------------------------------------------
# Measured in phase 0: for one racing field TSan reports ONE of several
# possible line pairs (after a report it resets that address's shadow state,
# so the second pair on the same byte never gets its own report), and line
# numbers move under every rebase. So the signature normalises to:
#
#   for each `WARNING: ThreadSanitizer: data race` block, take each of the two
#   access stacks; in each, the FIRST frame whose file lies under source/;
#   reduce it to `symbol@basename` with the :line dropped; sort the two keys
#   and join them with " ^ ". Frames in Phobos/druntime/libc never enter a
#   signature.
#
# A block whose two stacks contain no source/ frame at all normalises to the
# literal `<no-source-frame>` and is reported as such rather than dropped.
#
# ROW FORMAT
#   class | scenario | signature | date | task | one reason
#   class    ∈ required, tolerated
#   scenario ∈ selfcheck, sweep, shutdown, bridge, parallel
#
# Blank lines and `#` lines are ignored. A row without a task is not accepted
# at review. `required` is earned, not assumed: a finding enters it only after
# three consecutive reproductions; anything else is `tolerated` with the reason
# written down.
